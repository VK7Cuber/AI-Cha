# Описание логики работы терминала, который планируется собрать для кафе AI Cha #
 
 ## Конструкция терминала ##
 Терминал, который планируется собрать как прототип терминала для кафе AI Cha и на котором будут проводиться тесты, будет состоять из следующий компонентов:
 - *Одноплатный компьютер Orange Pi Zero 3 (4Gb оперативной памяти)* - главный мозг устройства, который обеспечивает основную работу. Операционная система - Linux (Ubuntu). Но предварительные тесты будут проводиться на ноутбуке Asus ZenBook (Windows 11).
 - *Петличный проводной микрофон* - маленький микрофон, который подключается к Orange Pi по USB 2.0 и передаёт голос пользователя в программу
 - *Сенсорный экран* - экран, на который будет выводится изображение с Orange Pi и через который будет осуществляться управление устройством. Диагональ - 10,1 дюйма (в дальнейшем возможно увеличение размера экрана, но для экономии средств, затраченных на сборку прототипа терминала, был оптимальный по соотношению цены и удобства использования экран). К Orange Pi экран подключается через USB 2.0 и HDMI.
 - *Колонки для вывода звука* - простые динамики. Возможно два варианта: использование встроенных в сенсорный экран динамиков или двух внешних динамиков Aiyima мощностью по 5W каждый, подключённых через усилитель.

 ## Предположительная логика работы ##
 1. В кафе будет установлен роутер, который создаёт WiFi сеть для гостей (без пароля, менее быструю), и специальную сеть для работы терминалов, более быструю и надёжную, подключение к которой происходит только по специальному паролю.
 2. В кафе также установлен специальный, мощный персональный компьютер, цель которого - запуск и хостинг сервера на локальной сети кафе. 
 3. Каждый терминал в кафе при включении подключается к более мощной и защищённой паролем WiFi-сети и заходит на сервер, который раздаёт персональный компьютер в кафе. На сервере как раз представлен весь интерфейс терминала. После включения терминала и подключения к серверу включается полноэкранный режим просмотра, и терминал готов к работе.
 4. Далее терминал работает так же, как компьютер, подключенный к удалённому сайту. Обработка голоса и другие взаимодействия с различными AI-агентами осуществляется через WebSocket и различные API.
 5. После формирования и оплаты заказа, заказ пользователя записывается в локальную базу данных, лежащую всё на том же ПК в кафе, на котором запущен сервер с интерфейсом терминала. 
 6. У сотрудников кафе также есть свой небольшой терминал, но он уже подключается к специальной странице на том же сервере, на ней отображаются заказы клиентов. После выполнения заказов, сотрудник нажимает на специальную кнопку на своём терминале, расположенную рядом с заказом пользователя. При этом на главном экране кафе, который висит над стойкой выдачи заказов, который также подключён к главному серверу, отображаются заказы и степень их готовности. После того, как сотрудник кафе нажимает кнопку, которая означает, что конкретный заказ готов, на главном экране выводится соответствующее сообщение. 

## 💡 Предлагаемые варианты архитектуры ПО и технологического стека (2025)

Ниже приведены три практических варианта реализации экосистемы терминалов AI Cha с учётом ограниченных ресурсов Orange Pi Zero 3 и необходимости быстрого голосового взаимодействия с пользователем. Все решения основаны на HTML / CSS / JavaScript-стеке, но различаются по месту исполнения бизнес-логики и AI-обработки.

### Вариант A — «Тонкий клиент + локальный сервер» (рекомендуемый для MVP)

1. **Frontend**
   - React + Vite (или SvelteKit) — сборка статических SPA-файлов.
   - Деплой напрямую на локальном сервере (мощный ПК) и раздача через Nginx.
   - Orange Pi загружает интерфейс как обычный веб-клиент (kiosk-mode Chromium) и кэширует его через Service Worker, что обеспечивает мгновенный старт после первой загрузки.
2. **Голосовой стек**
   - STT → Yandex SpeechKit **gRPC streaming** (низкая латентность <300 мс).
   - TTS → Yandex SpeechKit (кэшируем часто используемые фразы на сервере).
   - Обработка аудио выполняется на ПК; Orange Pi лишь захватывает и стримит звук по WebSocket.
3. **AI-агент**
   - OpenAI GPT-4o (cloud) или локальный Llama-3 8B Q-k в контейнере на ПК.
   - Абстракция в виде microservice `ai-dialog-service` (Node + Fastify).
4. **Заказы и кухня**
   - `order-service` (Go или Node) + PostgreSQL.
   - Сообщения о статусах — Redis Pub/Sub или MQTT (легковесно и realtime).
   - Kitchen Display & Staff Panel — те же веб-страницы, доступные с авторизацией.
5. **Плюсы**
   - Минимальная нагрузка на Orange Pi (рендер и запись микрофона).
   - Централизованное кэширование и логирование на ПК.
   - Лёгкое обновление: заменили bundle на сервере — все терминалы перезагрузились.
6. **Минусы**
   - Нужна надёжная локальная сеть; при падении сервера все терминалы недоступны.

### Вариант B — «PWA с частичным оффлоадом»

1. Orange Pi хранит полный PWA-cache (React + IndexedDB) и может работать в offline-режиме для отображения меню и формирования базовых заказов.
2. Голосовой диалог всё равно стримится на сервер для AI-обработки.
3. При обрыве связи — фоллбэк на текстовые кнопки без речи; заказы ставятся в offline-очередь (Workbox) и синхронизируются при восстановлении.
4. **Плюсы**: терминал продолжает работать при кратковременных сбоях Wi-Fi; меньше трафика.
5. **Минусы**: усложнение логики синхронизации, больший размер кода на Orange Pi.

### Вариант C — «Толстый клиент (Electron) + edge-AI»

1. Electron-пакет с встроенным UI + локальными WASM-модулями:
   - Vosk-WASM для offline STT (русский),
   - Silero-TTS или Coqui-TTS в WASM для быстрых реплик.
2. AI-модель — quantized Gemma 2B через GGUF + llama.cpp — запускается на Orange Pi CPU с 4 GB RAM (реально, но latency >5 с).
3. Заказы пишутся напрямую в SQLite, периодически пушатся на сервер.
4. **Плюсы**: Терминал автономен, работает даже при полном отсутствии сети.
5. **Минусы**: Высокая задержка речи, нагрузка на CPU, риск перегрева; усложнённые обновления.

### Сравнительная таблица
| Критерий                | Вариант A | Вариант B | Вариант C |
|-------------------------|-----------|-----------|-----------|
| Латентность речи        | ⭐ 200-400 мс | ⭐⭐ 300-600 мс | 🔸 >4 с |
| Устойчивость к оффлайн  | 🔸 низкая | ⭐ средняя | ⭐⭐ высокая |
| Нагрузка на Orange Pi   | ⭐ низкая | ⭐⭐ средняя | 🔸 высокая |
| Сложность разработк    | ⭐ низкая | ⭐⭐ средняя | 🔸 высокая |
| Скорость обновлений UI  | ⭐ мгновенно | ⭐ мгновенно | 🔸 требует repack |

> **Рекомендация:** начать с Варианта A — он быстрее в разработке и демонстрирует лучший пользовательский опыт; по мере роста кафе можно добавить оффлайн-механику из Варианта B.

## ⚙️ Ключевые технологические решения

1. **Kiosk-браузер**: `chromium --kiosk --app=http://server/terminal --disable-pinch` + автозапуск через systemd на Orange Pi.
2. **Аудио поток**: WebRTC (Mediasoup) или WebSocket с Opus-кодеком 16 kHz; апируем over gRPC на сервер.
3. **DevOps**: Docker Compose на ПК: `nginx`, `ai-dialog-service`, `order-service`, `postgres`, `redis`.
4. **CI/CD**: GitHub Actions → Watchtower для hot-reload контейнеров.
5. **Безопасность**: VLAN для терминалов + mTLS между Orange Pi и сервером.
6. **Мониторинг**: Prometheus + Grafana (CPU/latency), Sentry для фронта.

## 🗣️ Улучшение диалога и UX
- Реплики AI не дольше 3-4 секунд; синтезируем в параллель с анализом ответа.
- Pre-warm контекст LLM (system prompt) для каждого нового клиента.
- Кэш из 100 частых TTS-фраз хранится на Orange Pi (RAMDisk) → нулевая задержка приветствий.
- Используем микрофон-активацию (VAD) вместо кнопки «Говорите», чтобы ощущения были «как Siri».
