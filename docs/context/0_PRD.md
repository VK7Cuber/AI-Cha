# 🍃 AI-Cha Terminal - Техническое задание (PRD)

## 📋 Общая информация о продукте

### Название продукта
**AI-Cha Terminal** - Терминальная система для чайного кафе с AI-агентом для персонализированного подбора напитков

### Целевая платформа
- **Основная платформа**: Linux (Ubuntu) на одноплатных компьютерах Orange Pi Zero 3
- **Форм-фактор**: Сенсорный терминал/киоск с экраном 10.1 дюйма
- **Архитектура**: Тонкий клиент (браузер в kiosk-режиме) + централизованный сервер в кафе
- **Технологический стек**: React + Vite (frontend), Node.js (backend), Docker Compose
- **Тестовая среда**: Ноутбук Asus ZenBook (Windows 11) для разработки и первичных тестов
- **Местоположение**: Терминалы в чайном кафе AI-Cha

### Целевая аудитория
- **Основная**: Посетители чайного кафе
- **Возрастная группа**: 16-65 лет (все возрастные категории)
- **Языковые предпочтения**: Русскоязычные и китайскоязычные клиенты

### Основная ценность продукта
Терминал позволяет посетителям получить персонализированные рекомендации напитков на основе разговора с AI-агентом, который анализирует настроение, предпочтения и культурные особенности клиента.

---

## 🎯 Основной пользовательский сценарий

### Упрощенный путь пользователя:
1. **Подход к терминалу** - клиент видит приветственный экран
2. **Выбор режима взаимодействия** - "Подобрать товар" или "Обычный заказ"
3. **AI-диалог** (для режима подбора) - голосовая беседа с AI-агентом до 1 минуты
4. **Получение рекомендаций** - персонализированный список напитков
5. **Формирование заказа** - добавление товаров в корзину
6. **Оплата** - выбор способа оплаты и завершение транзакции
7. **Оценка сервиса** - обратная связь от клиента

## 🔧 Технические требования

### Архитектура системы (Вариант A - Тонкий клиент + локальный сервер)

#### Общая концепция:
Система построена по принципу централизованного сервера в кафе, к которому подключаются все терминалы как веб-клиенты. Вся тяжелая обработка (AI-диалоги, распознавание речи, бизнес-логика) выполняется на мощном сервере, а терминалы Orange Pi отвечают только за отображение интерфейса и захват звука/касаний.

#### Frontend (клиентская часть):
- **Фреймворк**: React 18+ с TypeScript
- **Сборщик**: Vite для быстрой сборки и горячей перезагрузки
- **UI библиотеки**: Tailwind CSS или styled-components для стилизации
- **Анимации**: Lottie для сложных анимаций, CSS transitions для базовых
- **PWA**: Service Worker для кэширования статических файлов (мгновенная загрузка после первого раза)
- **Формат**: Одностраничное приложение (SPA) с HTML/CSS/JavaScript

#### Backend (серверная часть):
- **Основной сервер**: Node.js с фреймворком Fastify (высокая производительность)
- **Архитектура**: Микросервисы в Docker-контейнерах
  - `ai-dialog-service` - обработка AI-диалогов и генерация рекомендаций
  - `order-service` - управление заказами и каталогом товаров
  - `nginx` - раздача статических файлов фронтенда и reverse proxy
- **База данных**: PostgreSQL 15+ для хранения заказов, товаров, аналитики
- **Очереди сообщений**: Redis Pub/Sub для real-time обновлений статусов заказов
- **Управление**: Docker Compose для оркестрации всех сервисов

#### AI и голосовые технологии:
- **Speech-to-Text (STT)**: 
  - Yandex SpeechKit с gRPC streaming протоколом
  - Латентность распознавания: <300 мс
  - Язык: русский с высокой точностью распознавания
- **Text-to-Speech (TTS)**: 
  - Yandex SpeechKit для генерации голоса AI-агента
  - Голос: женский, дружелюбный тон
  - Кэширование частых фраз (приветствия, типовые вопросы) на сервере для мгновенного воспроизведения
- **AI-модель для диалогов**: 
  - Вариант 1: OpenAI GPT-4o (облачный, быстрый, высокое качество)
  - Вариант 2: Llama-3 8B с квантизацией (локальный на сервере, без интернета)
- **Обработка аудио**: 
  - Терминал захватывает звук с микрофона и стримит через WebSocket на сервер
  - Кодек: Opus 16 kHz для оптимального качества и размера
  - VAD (Voice Activity Detection) для автоматического определения начала/конца речи

### Аппаратные компоненты терминала

#### Основной блок - Orange Pi Zero 3:
- **Процессор**: Allwinner H618 (4-ядерный ARM Cortex-A53, 1.5 GHz)
- **Оперативная память**: 4 GB LPDDR4
- **Операционная система**: Ubuntu 22.04 LTS (Linux)
- **Роль**: Запуск браузера Chromium в kiosk-режиме, захват аудио, рендеринг UI
- **Примечание**: Минимальная нагрузка благодаря архитектуре тонкого клиента

#### Сенсорный экран:
- **Диагональ**: 10.1 дюйма (компактный формат для прототипа)
- **Разрешение**: 1280x800 пикселей (WXGA)
- **Подключение**: 
  - HDMI для видеосигнала
  - USB 2.0 для сенсорного ввода
- **Ориентация**: Портретная или ландшафтная (настраивается)
- **Примечание**: В будущем возможно увеличение до 15-21 дюйма

#### Микрофон:
- **Тип**: Петличный проводной микрофон
- **Подключение**: USB 2.0 к Orange Pi
- **Особенности**: Направленный захват звука, базовое шумоподавление
- **Задача**: Передача голоса пользователя в программу для распознавания

#### Аудиовыход:
- **Вариант 1**: Встроенные динамики сенсорного экрана (простое решение)
- **Вариант 2**: Два внешних динамика Aiyima по 5W каждый + усилитель (лучшее качество)
- **Задача**: Воспроизведение голоса AI-агента и системных звуков

### Сетевая инфраструктура кафе

#### WiFi-сети:
- **Гостевая сеть**: 
  - Без пароля
  - Ограниченная скорость
  - Для посетителей с личными устройствами
- **Служебная сеть**: 
  - Защищена надежным паролем
  - Высокая скорость и приоритет
  - Только для терминалов, сервера и служебных устройств

#### Центральный сервер кафе:
- **Железо**: Мощный персональный компьютер (рекомендуемые характеристики):
  - Процессор: Intel i5/i7 или AMD Ryzen 5/7 (минимум 6 ядер)
  - ОЗУ: 16-32 GB для комфортной работы AI-моделей и базы данных
  - SSD: 500 GB+ для быстрого доступа к данным
  - Сеть: Гигабитный Ethernet
- **ПО**: Ubuntu Server 22.04 + Docker + Docker Compose
- **Функции**: 
  - Хостинг веб-интерфейса терминалов (Nginx)
  - Обработка AI-диалогов и голоса
  - База данных заказов и товаров
  - Real-time коммуникация с терминалами

#### Клиентские терминалы (Orange Pi):
- **Режим работы**: 
  - При включении автоматически подключаются к служебной WiFi-сети
  - Запускают Chromium в kiosk-режиме с адресом сервера
  - Команда: `chromium --kiosk --app=http://192.168.1.100:8080/terminal --disable-pinch`
- **Автозапуск**: Настроен через systemd для автоматического старта при включении
- **Обновления**: Автоматические при обновлении кода на сервере (без действий на терминале)

#### Терминал для сотрудников:
- **Устройство**: Планшет или небольшой компьютер с сенсорным экраном
- **Интерфейс**: Специальная веб-страница на том же сервере (`http://сервер/staff`)
- **Функции**: 
  - Просмотр активных заказов клиентов
  - Управление статусами заказов (принят, готовится, готов)
  - Авторизация для доступа
- **Взаимодействие**: Real-time обновления через WebSocket/Redis

#### Главный экран отображения заказов:
- **Расположение**: Над стойкой выдачи заказов в зале
- **Устройство**: Большой монитор или телевизор, подключенный к серверу (или отдельному Orange Pi)
- **Интерфейс**: Веб-страница (`http://сервер/display`)
- **Отображение**: 
  - Список активных заказов
  - Степень готовности каждого заказа
  - Уведомления о готовых заказах
- **Обновление**: Автоматическое в реальном времени при изменении статусов

### DevOps и развертывание

#### Контейнеризация:
- **Docker Compose** для управления всеми сервисами на центральном сервере:
  ```
  services:
    - nginx (раздача фронтенда)
    - ai-dialog-service (Node.js)
    - order-service (Node.js или Go)
    - postgres (база данных)
    - redis (очередь сообщений)
  ```

#### CI/CD:
- **Репозиторий**: Git (GitHub/GitLab) для хранения кода
- **Автоматизация**: GitHub Actions для сборки и тестирования
- **Обновления**: Watchtower для автоматического обновления контейнеров при изменении образов

#### Мониторинг и логирование:
- **Производительность**: Prometheus + Grafana для отслеживания CPU, памяти, латентности
- **Ошибки фронтенда**: Sentry для отлова и анализа ошибок в браузере
- **Логи сервисов**: Centralized logging через Docker logs

#### Безопасность:
- **Сетевая изоляция**: VLAN для разделения служебной и гостевой сетей
- **Шифрование**: mTLS между терминалами и сервером для защиты данных
- **API-ключи**: Хранятся в переменных окружения Docker, не в коде
- **Обновления**: Регулярные обновления ОС и зависимостей

### Интеграции

#### Каталог товаров:
- **Управление**: Админ-панель для редактирования товаров, цен, описаний
- **Синхронизация**: Автоматическое обновление на всех терминалах при изменении
- **Мультиязычность**: Хранение названий и описаний на русском и китайском

#### Платежные системы (будущая интеграция):
- **Банковские карты**: Эквайринг через POS-терминал или API платежного шлюза
- **СБП (Система Быстрых Платежей)**: Генерация QR-кодов для оплаты
- **Карта лояльности AI Cha**: Собственная система бонусов и скидок

#### Аналитика:
- **Сбор данных**: 
  - Выбор клиентов (AI-подбор vs обычный заказ)
  - Эффективность AI-рекомендаций
  - Популярные товары и время заказа
  - Средний чек и время обслуживания
- **Хранение**: PostgreSQL с периодическим архивированием
- **Визуализация**: Дашборды в Grafana или отдельный BI-инструмент

## 🤖 AI и голосовые технологии

### AI-агент для диалога:

#### Характер и персональность:
- **Тон общения**: Дружелюбный, гостеприимный
- **Стиль**: Неформальный, но вежливый  
- **Культурная адаптация**: Знание китайской чайной культуры
- **Эмоциональный интеллект**: Адаптация к настроению клиента

#### Логика диалога:
- **Начальные вопросы**: О настроении и предпочтениях
- **Адаптивные вопросы**: На основе предыдущих ответов
- **Завершающий анализ**: Сведение к 3-6 рекомендациям
- **Обоснование выбора**: Объяснение почему именно эти напитки

#### Примеры сценариев:
```
Сценарий 1 - Плохое настроение:
AI: "Здравствуйте! Как дела, как настроение?"
Клиент: "Плохо как-то сегодня..."
AI: "Понимаю... А что расстроило? Работа, погода?"
→ Рекомендации: успокаивающие чаи (ромашка, мелисса)

Сценарий 2 - Хорошее настроение:
AI: "Привет! Вижу, отличное настроение!"
Клиент: "Да, день удался!"  
AI: "Здорово! Хочется чего-то особенного или привычного?"
→ Рекомендации: праздничные чаи, новинки

Сценарий 3 - Неопределенность:
AI: "Знаете, что хотите, или доверитесь мне?"
Клиент: "Не знаю... Посоветуйте"
AI: "Любите ли экспериментировать или предпочитаете проверенное?"
→ Рекомендации: на основе характера ответов
```

### Алгоритм подбора напитков:

#### Факторы анализа:
- **Эмоциональное состояние**: грустный/веселый/усталый/энергичный
- **Вкусовые предпочтения**: сладкий/горький/кислый/пряный
- **Температурные предпочтения**: горячий/холодный
- **Время суток**: утро/день/вечер
- **Ситуация**: один/с друзьями/деловая встреча
- **Опыт с чаем**: новичок/любитель/эксперт

#### Матрица рекомендаций:
```
Усталость + утро → Крепкий черный чай, матча
Стресс + вечер → Травяные чаи, ромашка
Веселье + компания → Фруктовые чаи, пуэр
Романтика + двое → Жасминовый чай, улун
```

## 📝 Заключение

Данный PRD определяет полные требования к терминальной системе AI-Cha для чайного кафе с русско-китайской тематикой. Документ покрывает все аспекты пользовательского опыта, технической реализации, интеграции с AI и качества продукта.

### Утвержденная архитектура: Вариант A (Тонкий клиент + локальный сервер)

**Ключевые технические решения:**
- **Железо терминала**: Orange Pi Zero 3 (4GB RAM) с экраном 10.1", петличным микрофоном и динамиками
- **Архитектура**: Централизованный сервер в кафе + терминалы как веб-клиенты в kiosk-режиме
- **Frontend**: React 18+ с Vite, HTML/CSS/JavaScript, PWA с кэшированием
- **Backend**: Node.js (Fastify) с микросервисами в Docker Compose
- **База данных**: PostgreSQL 15+ для заказов и товаров, Redis Pub/Sub для real-time обновлений
- **AI и голос**: 
  - Yandex SpeechKit (STT/TTS) с латентностью <300 мс
  - OpenAI GPT-4o или локальный Llama-3 8B для диалогов
  - Потоковая передача аудио через WebSocket с кодеком Opus
- **Сеть**: Двойная WiFi (гостевая + служебная), все терминалы и экраны подключены к одному серверу
- **Тестирование**: Первичная разработка и тесты на ноутбуке Asus ZenBook (Windows 11)

**Преимущества выбранного решения:**
- Минимальная нагрузка на Orange Pi (только рендер и захват звука)
- Быстрые обновления интерфейса (обновили сервер → все терминалы обновились)
- Низкая латентность голосового диалога (200-400 мс)
- Централизованное управление и мониторинг
- Простота разработки и отладки
- Возможность тестировать весь стек на одном компьютере

**Подтвержденные границы MVP:**
- Заглушки вместо реальной оплаты (будущая интеграция с эквайрингом)
- Только русский язык для AI-диалогов (китайский присутствует в UI)
- Базовая система рекомендаций без машинного обучения
- OpenAI GPT-4o для начала (локальная Llama-3 как альтернатива)
- Стандартные голосовые API без кастомизации голоса

**Экосистема кафе:**
1. **Терминалы для клиентов** (Orange Pi) - заказ через AI-диалог или меню
2. **Терминал для сотрудников** - управление заказами и их статусами
3. **Главный экран** - отображение готовых заказов для клиентов
4. **Центральный сервер** - мозг всей системы на мощном ПК
5. **Служебная WiFi-сеть** - быстрая и защищенная связь между компонентами
